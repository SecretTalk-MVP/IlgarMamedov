# SecretTalk — Configuration Standard

## 1. Назначение

Этот документ определяет единый способ работы с конфигурацией SecretTalk.

## 2. Configuration ownership

Конфигурация должна иметь одного определённого владельца.

Настройки не должны дублироваться между:

- index.js;
- router.js;
- modules;
- отдельными service-файлами.

## 3. Environment variables

Секретные и environment-specific значения должны находиться в окружении.

Например:

- Telegram token;
- API keys;
- database credentials;
- production configuration.

Они не должны записываться непосредственно в исходный код.

## 4. Module configuration

Настройки конкретного модуля должны находиться рядом с модулем либо в утверждённом общем configuration layer.

Например:

`modules/aida/`

может содержать настройки, относящиеся только к AiDa.

## 5. Shared configuration

Общие настройки приложения могут находиться в общем configuration layer.

Модули используют их через определённый интерфейс.

Не следует копировать одну и ту же настройку в несколько модулей.

## 6. Environment separation

Production и development configuration должны быть разделены.

Изменение production configuration не должно требовать изменения бизнес-логики модулей.

## 7. Defaults

Если для настройки предусмотрено значение по умолчанию, оно должно быть определено в одном месте.

Нельзя создавать разные defaults для одной настройки в разных файлах.

## 8. Validation

При запуске необходимо проверять обязательные configuration values.

Если обязательная настройка отсутствует, приложение должно сообщить об ошибке и не продолжать работу в некорректном состоянии.

## 9. Security

Configuration не должна содержать:

- hardcoded API keys;
- passwords;
- tokens;
- private credentials.

Секреты не должны попадать в Git или logs.

## 10. Migration

При переносе configuration:

1. создать новую конфигурацию;
2. подключить её;
3. проверить;
4. удалить старый источник;
5. проверить отсутствие старых ссылок.

## 11. Главное правило

Одна настройка — один авторитетный источник.

Конфигурация должна быть отделена от бизнес-логики и не должна размножаться по проекту.
