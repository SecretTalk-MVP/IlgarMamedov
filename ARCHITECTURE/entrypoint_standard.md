# SecretTalk — Entrypoint Standard

## 1. Назначение

Этот документ определяет единый стандарт пользовательских точек входа в SecretTalk.

## 2. Что является Entrypoint

Entrypoint — это действие пользователя, которое запускает функцию:

- кнопка Menu;
- команда;
- callback;
- текстовое действие;
- другой пользовательский trigger.

## 3. Основная цепочка

Каждый user-facing entrypoint должен иметь однозначную цепочку:

`USER ACTION → ENTRYPOINT → ROUTER → MODULE → RESULT`

## 4. Владелец

Каждый entrypoint имеет одного владельца.

Владелец определяет:

- какой модуль выполняет функцию;
- какой route используется;
- какое состояние необходимо;
- какой результат возвращается пользователю.

## 5. Регистрация

Для каждого entrypoint необходимо определить:

`ENTRYPOINT`

↓

`MODULE OWNER`

↓

`ROUTER ROUTE`

↓

`USER STATE`

↓

`RESULT`

## 6. Запрет дублирования

Нельзя иметь:

- несколько активных обработчиков одного entrypoint;
- одну кнопку, ведущую к разным модулям;
- старый entrypoint после миграции;
- прямой обход Router без архитектурного решения.

## 7. Проверка

Перед завершением интеграции проверить:

1. пользователь может вызвать entrypoint;
2. entrypoint достигает Router;
3. Router выбирает правильный маршрут;
4. Router передаёт управление правильному модулю;
5. модуль выполняет функцию;
6. результат возвращается пользователю;
7. другие модули не перехватывают действие.

## 8. Изменение

Если entrypoint переносится на новый модуль:

`NEW ENTRYPOINT → NEW ROUTE → NEW MODULE`

После проверки старая цепочка удаляется.

## 9. Главное правило

Наличие функции в коде не означает наличие рабочего entrypoint.

Entrypoint считается подключённым только после прохождения полного пользовательского пути.
