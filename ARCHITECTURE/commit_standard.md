# SecretTalk — Commit Standard

## 1. Назначение

Этот документ определяет правила создания Git commit после завершения изменения.

## 2. Commit только после проверки

Commit выполняется только после:

`IMPLEMENT → VERIFY → INTEGRATE → TEST`

Нельзя использовать commit как способ сохранить незавершённую архитектуру.

## 3. Один архитектурный шаг

Один commit должен по возможности представлять один законченный архитектурный шаг.

Примеры:

- создание нового модуля;
- подключение Router;
- миграция старой реализации;
- удаление legacy;
- отдельное исправление.

## 4. Перед commit

Проверить:

- модуль работает;
- Router работает;
- Menu работает, если требуется;
- Index работает, если изменялся;
- старый код не активен;
- нет дублирующих обработчиков;
- полный пользовательский сценарий работает.

## 5. Commit message

Сообщение commit должно кратко описывать фактическое изменение.

Примеры:

`Add AiDa memory module`

`Connect matchmaking to router`

`Remove legacy AiDa handler`

Не использовать сообщения, которые не объясняют изменение.

## 6. Запрет незавершённого commit

Не выполнять commit, если:

- новый модуль не проверен;
- интеграция не завершена;
- старый и новый код одновременно активны;
- Router не подключён;
- пользовательский flow не работает.

## 7. После commit

После успешного commit следующий этап:

`DEPLOY`

После deploy:

`PRODUCTION TEST`

Commit не означает, что функция уже работает в production.

## 8. Главное правило

Commit фиксирует завершённый проверенный архитектурный шаг, а не промежуточное состояние разработки.
