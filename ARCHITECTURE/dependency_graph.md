# SecretTalk — Dependency Graph Standard

## 1. Назначение

Этот документ определяет допустимое направление зависимостей между архитектурными слоями SecretTalk.

## 2. Основное направление

Зависимости должны двигаться от верхнего уровня приложения к функциональным модулям:

`INDEX → ROUTER → MODULE → SERVICE / DATABASE`

При этом нижний слой не должен становиться владельцем верхнего слоя.

## 3. Index

`index.js` может подключать:

- Router;
- Menu;
- root-level services;
- startup components.

Модули не должны подключать `index.js`.

## 4. Router

Router может подключать:

- Menu;
- module public entrypoints;
- navigation helpers;
- routing guards.

Router не должен подключать внутреннюю бизнес-логику модуля.

## 5. Module

Модуль может подключать:

- собственные внутренние файлы;
- общие сервисы;
- database layer;
- утверждённые public APIs других модулей.

Модуль не должен подключать внутренние файлы другого модуля без архитектурного решения.

## 6. Shared services

Shared service может использоваться несколькими модулями.

Он не должен зависеть от конкретного пользовательского модуля.

## 7. Запрещённое направление

Не допускаются зависимости:

`MODULE → ROUTER`

`MODULE → INDEX`

`SERVICE → MODULE`

`MENU → MODULE BUSINESS LOGIC`

если они не предусмотрены отдельным архитектурным решением.

## 8. Circular dependency

Не допускаются циклы:

`A → B → A`

или:

`A → B → C → A`

При обнаружении такого цикла архитектура должна быть пересмотрена.

## 9. Legacy

Новая архитектура не должна создавать зависимости на legacy-код без явного решения о миграции.

После миграции legacy dependency должна быть удалена.

## 10. Проверка

Перед завершением архитектурного изменения необходимо проверить:

- новые imports;
- новые require;
- направление зависимостей;
- циклические зависимости;
- legacy dependencies;
- зависимости между модулями.

## 11. Главное правило

Каждый слой должен зависеть только от разрешённых нижестоящих слоёв или от официальных public interfaces.

Архитектурный поток должен оставаться понятным:

`INDEX → ROUTER → MODULE → SERVICE → DATABASE`
