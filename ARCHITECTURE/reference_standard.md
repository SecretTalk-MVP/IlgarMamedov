# SecretTalk — Reference Standard

## 1. Назначение

Этот документ определяет правила хранения архитектурных и исторических материалов, которые не являются частью runtime-приложения.

## 2. Reference

Reference — это материал, который сохраняется для:

- истории проекта;
- анализа предыдущей архитектуры;
- будущего проектирования;
- понимания принятых ранее решений.

Reference не является активной реализацией.

## 3. Runtime

Reference-файлы не должны подключаться к:

- `index.js`;
- `router.js`;
- `menu.js`;
- активным модулям;
- runtime services.

## 4. Архитектурная ценность

Перед удалением старого документа необходимо определить, содержит ли он:

- архитектурное решение;
- описание предыдущей реализации;
- важное техническое объяснение;
- информацию, необходимую для миграции.

Если содержит — сохранить как `REFERENCE`.

## 5. Неактивность

Само наличие Reference-файла не означает, что описанная в нём архитектура является действующей.

Действующая архитектура определяется актуальными:

`ARCHITECTURE/architecture.json`

и утверждёнными архитектурными стандартами.

## 6. Конфликт

Если Reference противоречит действующей архитектуре:

действующей считается актуальная архитектура.

Reference не должен использоваться как основание для возврата старой реализации без отдельного архитектурного решения.

## 7. Удаление Reference

Reference удаляется только если:

- он больше не содержит архитектурной ценности;
- информация полностью сохранена в актуальной документации;
- он не нужен для истории или миграции.

## 8. Главное правило

Reference сохраняет знания.

Runtime реализует функции.

Architecture определяет действующие правила.

Эти три понятия нельзя смешивать.
