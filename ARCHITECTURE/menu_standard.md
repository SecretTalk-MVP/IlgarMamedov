# SecretTalk — Menu Standard

## 1. Назначение

Menu является единой точкой создания пользовательских кнопок и команд меню.

Menu не содержит бизнес-логику модулей.

## 2. Основная схема

Пользовательская кнопка должна работать по цепочке:

`USER → MENU → ROUTER → MODULE → RESULT`

## 3. Ответственность Menu

Menu отвечает только за:

- отображение кнопок;
- названия пользовательских действий;
- структуру клавиатуры;
- передачу пользовательского действия дальше.

## 4. Запрет бизнес-логики

Menu не должен:

- выполнять бизнес-логику;
- напрямую управлять AI;
- напрямую выполнять matchmaking;
- самостоятельно изменять состояние модуля;
- дублировать Router.

## 5. Уникальность

Каждая пользовательская кнопка или команда должна иметь одного владельца.

Нельзя создавать несколько кнопок, которые ведут к разным реализациям одной функции.

## 6. Подключение нового пункта

Для нового пользовательского действия:

1. определить модуль-владелец;
2. определить Router route;
3. добавить кнопку в Menu;
4. связать кнопку с Router;
5. проверить полный user flow.

## 7. Удаление старого пункта

Если новая функция заменяет старую:

`NEW MENU ENTRY → ROUTER → NEW MODULE`

После проверки старая кнопка и её старый маршрут удаляются.

## 8. Главный принцип

Menu показывает.

Router направляет.

Module выполняет.

Эти ответственности не должны смешиваться.
