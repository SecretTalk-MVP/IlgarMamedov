# SecretTalk — Documentation Standard

## 1. Назначение

Этот документ определяет правила хранения и использования документации SecretTalk.

## 2. Архитектурные документы

Архитектурные правила находятся в:

`ARCHITECTURE/`

Эти документы определяют структуру, правила и порядок разработки.

## 3. Constitution

Обязательные правила разработки находятся в:

`PROJECT_DEVELOPMENT_CONSTITUTION/`

Конституция определяет общий принцип работы над проектом.

## 4. Один источник правила

Если правило уже существует в утверждённом документе, новый документ с тем же правилом не создаётся.

Сначала проверяется существующий документ.

При необходимости существующий документ дополняется.

## 5. Запрет дублирования

Нельзя создавать несколько документов, описывающих одно и то же правило, без явной архитектурной причины.

Например, не создавать второй:

`integration_standard.md`

если такой документ уже существует.

## 6. Документация не является runtime-кодом

Документы архитектуры не должны подключаться к:

- index.js;
- router.js;
- modules;
- runtime services.

Они используются как источник правил для разработки и будущей автоматизации Governance Layer.

## 7. Документация должна соответствовать коду

Если архитектура изменена, соответствующие документы должны быть обновлены.

Запрещено оставлять утверждённую документацию, которая сознательно описывает уже отменённую архитектуру.

## 8. Reference Material

Старые архитектурные материалы могут сохраняться как:

`REFERENCE`

если они имеют историческую или проектную ценность.

Reference не является действующим runtime-правилом автоматически.

## 9. Перед созданием документа

Проверить:

1. существует ли уже такой документ;
2. описывает ли существующий документ необходимое правило;
3. можно ли дополнить существующий документ;
4. действительно ли нужен новый документ.

## 10. Главное правило

Сначала используем существующую документацию.

Потом дополняем её.

И только если существующей структуры недостаточно — создаём новый документ.

Цель документации:

`ONE RULE → ONE AUTHORITATIVE DOCUMENT`

а не большое количество дублирующих файлов.
