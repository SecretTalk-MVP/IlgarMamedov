# SecretTalk — Deployment Standard

## 1. Назначение

Этот документ определяет обязательный порядок публикации изменений SecretTalk.

## 2. Условие deploy

Deploy выполняется только после:

`IMPLEMENT → VERIFY → INTEGRATE → TEST → COMMIT`

Нельзя деплоить непроверенную архитектуру.

## 3. Перед deploy

Проверить:

- commit существует;
- рабочая версия соответствует commit;
- новый модуль подключён;
- старый модуль удалён из активного flow;
- Router работает;
- Menu работает, если требуется;
- Index работает, если изменялся.

## 4. Deploy

Deploy публикует именно проверенный commit.

Deploy не является заменой тестированию.

## 5. После deploy

Обязательно выполнить production test.

Минимальная проверка:

`USER ACTION → ROUTER → MODULE → RESPONSE`

## 6. Ошибка после deploy

Если production test не проходит:

1. остановить дальнейшие изменения;
2. определить точку отказа;
3. проверить logs;
4. определить причину;
5. исправить только установленную причину;
6. повторить verification;
7. создать новый commit;
8. повторить deploy;
9. повторить production test.

Не делать случайные изменения после неудачного deploy.

## 7. Rollback

Если исправление невозможно выполнить безопасно, используется rollback к последней подтверждённой рабочей версии.

Rollback не заменяет поиск причины.

После rollback необходимо определить причину сбоя до продолжения разработки.

## 8. Главное правило

`COMMIT` означает:

изменение зафиксировано.

`DEPLOY` означает:

изменение опубликовано.

`PRODUCTION TEST` означает:

изменение подтверждено в работающем приложении.

Это три разных этапа.
