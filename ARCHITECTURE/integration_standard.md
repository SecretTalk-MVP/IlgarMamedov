# SecretTalk — Integration Standard

## 1. Назначение

Этот документ устанавливает единый стандарт подключения любого модуля к приложению.

## 2. Основная схема

Пользовательская функция должна проходить по цепочке:

USER
→ MENU
→ ROUTER
→ MODULE
→ RESULT

При необходимости запуск приложения проходит через:

INDEX
→ ROUTER
→ MODULE

## 3. Router

Router является единой точкой маршрутизации.

Для каждого модуля определяется:

- точка входа;
- условие маршрутизации;
- состояние пользователя;
- передача управления модулю.

Стандартный вызов:

`module.handle(bot, msg)`

## 4. Menu

Если функция представлена кнопкой или пользовательской командой, она регистрируется только в одном месте.

Menu не содержит бизнес-логику модуля.

Menu только предоставляет пользователю точку входа.

## 5. Index

Index подключает только те компоненты, которые необходимы для запуска приложения.

Если Router уже управляет модулем, повторная маршрутизация через index запрещена.

## 6. Состояние пользователя

Если модуль работает только в определённом режиме пользователя, Router должен проверять состояние пользователя перед передачей сообщения модулю.

Пример:

`main → aida`

После перехода в режим AiDa сообщения передаются AiDa.

После выхода из режима AiDa сообщения больше не передаются AiDa.

## 7. Уникальность маршрута

Одна пользовательская команда должна иметь один маршрут.

Запрещено:

- несколько активных обработчиков одной команды;
- параллельная обработка одним сообщением нескольких модулей;
- передача сообщения старому модулю после подключения нового.

## 8. Подключение нового модуля

Новый модуль подключается следующим образом:

1. Создать модуль.
2. Проверить модуль отдельно.
3. Зарегистрировать его точку входа в Router.
4. Зарегистрировать пользовательскую точку входа в Menu, если требуется.
5. Зарегистрировать в Index только при необходимости.
6. Удалить старую реализацию.
7. Проверить полный маршрут.
8. Выполнить commit.

## 9. Проверка маршрута

Перед завершением интеграции необходимо проверить:

- пользователь видит кнопку или команду;
- команда достигает Router;
- Router определяет правильный режим;
- Router передаёт управление правильному модулю;
- модуль возвращает результат;
- результат отправляется пользователю;
- другие модули не перехватывают сообщение.

## 10. Запрет дублирования

После интеграции нового модуля старый маршрут должен быть удалён.

Нельзя оставлять:

`OLD MODULE + NEW MODULE`

или:

`OLD ROUTE + NEW ROUTE`

одновременно активными.

## 11. Критерий завершения

Модуль считается интегрированным только тогда, когда работает вся цепочка:

`MENU → ROUTER → MODULE → RESULT`

и отсутствует старая активная реализация той же функции.
