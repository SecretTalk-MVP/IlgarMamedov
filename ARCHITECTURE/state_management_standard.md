# SecretTalk — State Management Standard

## 1. Назначение

Этот документ определяет единый способ управления состоянием пользователя.

## 2. Владелец состояния

Состояние пользовательской навигации принадлежит центральному Router.

Модули не должны самостоятельно создавать независимые navigation stacks.

## 3. Основная модель

Каждый пользователь имеет собственное состояние:

`userId → current route/state`

Router определяет текущий режим пользователя и передаёт сообщение соответствующему модулю.

## 4. Переход

Переход между режимами выполняется через Router:

`CURRENT STATE → ROUTER → NEW STATE`

После перехода Router становится источником истины о текущем состоянии пользователя.

## 5. Module State

Модуль может хранить собственное внутреннее состояние, если оно относится исключительно к его бизнес-логике.

Такое состояние не должно заменять глобальное состояние Router.

## 6. Выход

Выход из режима должен явно изменять состояние пользователя.

Например:

`main → aida`

После выхода:

`aida → main`

После выхода AiDa больше не получает обычные сообщения пользователя.

## 7. Back

Глобальная команда «Назад» управляется Router.

Модуль не должен самостоятельно обходить глобальную навигацию.

## 8. Запрет конфликтующих состояний

Нельзя одновременно считать пользователя активным в двух взаимоисключающих режимах без специального архитектурного решения.

Пример запрещённого состояния:

`aida + matchmaking`

если архитектура не предусматривает такую комбинацию.

## 9. Проверка

После изменения состояния необходимо проверить:

- правильный вход;
- правильный текущий state;
- правильную передачу сообщений;
- правильный выход;
- работу «Назад»;
- отсутствие перехвата сообщений другим модулем.

## 10. Главное правило

`Router owns navigation state.`

Модуль отвечает за свою функцию.

Router отвечает за то, какой модуль имеет право получить сообщение пользователя.
