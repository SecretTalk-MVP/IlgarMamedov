# SecretTalk — Legacy Management Standard

## 1. Назначение

Этот документ определяет порядок работы со старым кодом и архитектурными остатками.

## 2. Старый код не считается активным автоматически

Файл является активным только если:

- приложение его запускает;
- Router его вызывает;
- другой активный модуль его использует;
- он участвует в пользовательском сценарии.

Само наличие файла в репозитории не означает, что он является частью рабочей архитектуры.

## 3. Классификация

Каждый старый компонент относится к одной категории:

- ACTIVE — используется приложением;
- LEGACY — старый код, который ещё требует миграции;
- REFERENCE — сохранён как архитектурный материал;
- UNUSED — не используется;
- OBSOLETE — заменён новой реализацией.

## 4. Замена

При замене:

NEW
→ VERIFY
→ INTEGRATE
→ VERIFY
→ REMOVE OLD
→ VERIFY

Старая реализация удаляется только после успешной интеграции новой.

## 5. Запрет параллельных реализаций

Для одной функции запрещено одновременно использовать:

OLD IMPLEMENTATION
+
NEW IMPLEMENTATION

если архитектурой специально не предусмотрен переходный период.

## 6. Поиск ссылок

Перед удалением необходимо проверить:

- require/import;
- Router;
- Index;
- Menu;
- callbacks;
- handlers;
- services;
- configuration;
- database dependencies.

## 7. Архитектурные документы

Архитектурный материал не удаляется только потому, что он не используется runtime.

Если документ сохраняется для будущего использования, он классифицируется как:

`REFERENCE`

и не должен восприниматься как действующая реализация.

## 8. Удаление

Удаление выполняется только после определения статуса компонента.

Нельзя удалять файл только потому, что он выглядит старым.

Нельзя сохранять файл только потому, что он когда-то использовался.

## 9. Критерий очистки

Legacy-компонент может быть окончательно удалён, если:

- новая реализация работает;
- активных ссылок нет;
- пользовательский сценарий работает;
- компонент не является архитектурным Reference;
- компонент не требуется другой активной системе.

## 10. Главное правило

Мы не удаляем старое вслепую.

Мы не сохраняем старое без причины.

Каждый компонент должен иметь понятный статус и владельца.
