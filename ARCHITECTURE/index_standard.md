# SecretTalk — Index Standard

## 1. Назначение

`index.js` является корневым orchestrator приложения.

Он запускает приложение и соединяет основные системные компоненты.

## 2. Ответственность

Index отвечает за:

- создание Telegram Bot;
- запуск polling или другого transport lifecycle;
- подключение главного Router;
- подключение глобальных систем, необходимых при запуске;
- обработку ошибок верхнего уровня.

## 3. Запрет бизнес-логики

В `index.js` запрещено размещать:

- бизнес-логику модулей;
- логику AI;
- matchmaking;
- настройки пользователя;
- административную бизнес-логику;
- дублирующую маршрутизацию;
- состояние отдельных пользовательских экранов.

## 4. Router

Все пользовательские маршруты должны проходить через центральный Router.

Стандарт:

`Telegram → index.js → Router → Module`

Index не должен повторно обрабатывать сообщения, которые уже принадлежат Router.

## 5. Menu

Menu подключается через установленную архитектуру.

Index не должен самостоятельно реализовывать Menu actions.

## 6. Module Integration

Новый модуль подключается к Index только если ему действительно требуется root-level lifecycle integration.

Обычная пользовательская функция подключается через:

`Menu → Router → Module`

а не напрямую через Index.

## 7. Старый код

При замене старой реализации:

1. создать новую реализацию;
2. проверить её отдельно;
3. подключить через установленный слой;
4. проверить полный flow;
5. удалить старую реализацию из Index;
6. проверить отсутствие старых ссылок.

## 8. Критерий корректности

Index считается архитектурно корректным, если его можно прочитать как:

`START APPLICATION → INITIALIZE SYSTEMS → START ROUTER`

без необходимости понимать бизнес-логику отдельных модулей.

## 9. Главное правило

`index.js` должен оставаться тонким.

Если новый код можно разместить в отдельном модуле или Router без потери архитектурной целостности, он не должен добавляться в Index.
