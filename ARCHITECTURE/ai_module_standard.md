# SecretTalk — AI Module Standard

## 1. Назначение

Этот документ определяет правила создания и изменения AI-модулей SecretTalk.

## 2. Авторитетный AI-модуль

Каждый AI-персонаж должен иметь одного авторитетного владельца.

Для AiDa:

`modules/aida/`

Основные компоненты:

`aida.js` — поведение и публичный интерфейс.

`aida.system.md` — характер, идентичность и системные правила.

`aida.memory.js` — долговременная память.

## 3. Character

Характер AI-персонажа хранится внутри его модуля.

Другие character-файлы не должны параллельно определять его личность.

## 4. Memory

Память конкретного AI-персонажа должна иметь одного владельца.

Запрещено одновременно использовать несколько независимых систем памяти для одной и той же функции без архитектурного решения.

## 5. Shared AI infrastructure

Общие AI-сервисы могут использоваться несколькими модулями.

Например:

`OpenRouter Client`

является общей транспортной инфраструктурой.

Он не должен содержать характер конкретного персонажа.

## 6. AI Router integration

AI-модуль получает сообщения только тогда, когда Router определил, что пользователь находится в соответствующем AI-режиме.

Пример:

`main → aida`

После входа:

`USER MESSAGE → ROUTER → AIDA`

После выхода:

`USER MESSAGE → ROUTER → OTHER MODULE`

## 7. Context

Контекст AI должен формироваться только из утверждённых источников.

Минимально:

- системная идентичность;
- пользовательское сообщение;
- доступная долговременная память;
- необходимое состояние диалога.

Не допускается случайное подключение старого ContextBuilder или другого контекстного слоя без архитектурного решения.

## 8. Prompt

Системная идентичность AI должна иметь один авторитетный источник.

Для AiDa:

`modules/aida/aida.system.md`

Старый PromptBuilder не становится источником характера только потому, что он существует в репозитории.

## 9. Memory update

AI-модуль должен сохранять информацию только через утверждённый механизм памяти.

Явно сообщённые пользователем факты могут сохраняться.

Нельзя сохранять случайные предположения как факты.

## 10. AI module lifecycle

Изменение AI-модуля проходит:

`CHANGE`

→ `INDEPENDENT VERIFY`

→ `ROUTER VERIFY`

→ `MEMORY VERIFY`

→ `DIALOG TEST`

→ `REMOVE OLD`

→ `COMMIT`

→ `DEPLOY`

→ `PRODUCTION TEST`

## 11. AI architecture conflict

Если старые AI-компоненты конфликтуют с новой архитектурой:

STOP.

Не подключать старую систему автоматически.

Сначала определить, является ли старый компонент:

- ACTIVE;
- LEGACY;
- REFERENCE;
- UNUSED;
- OBSOLETE.

## 12. Главное правило

AI-персонаж является самостоятельным модулем.

Его характер, память и основная логика не должны постепенно расползаться по нескольким архитектурным слоям.

Для каждой AI-функции должен существовать один авторитетный источник.
