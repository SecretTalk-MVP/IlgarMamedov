# SecretTalk — Verification Standard

## 1. Назначение

Этот документ определяет обязательную проверку нового или изменённого кода.

## 2. Проверка модуля

До интеграции проверить:

- файл загружается;
- зависимости доступны;
- синтаксис корректен;
- публичный интерфейс существует;
- основная функция работает;
- ошибки обрабатываются.

## 3. Проверка Router

После интеграции проверить:

- Router загружается;
- маршрут зарегистрирован;
- правильный модуль получает событие;
- посторонний модуль не получает событие;
- состояние пользователя учитывается.

## 4. Проверка Menu

Если существует пользовательская точка входа:

- кнопка отображается;
- команда распознаётся;
- callback работает;
- маршрут ведёт в правильный модуль.

## 5. Проверка Index

Если изменён `index.js`:

- приложение запускается;
- новая регистрация работает;
- бизнес-логика в `index.js` не появилась;
- существующие функции не сломались.

## 6. Проверка старой реализации

После миграции проверить:

- старый импорт отсутствует;
- старый route отсутствует;
- старый handler не вызывается;
- старая реализация не получает пользовательские события;
- дублирование отсутствует.

## 7. Полный пользовательский тест

Проверяется реальный сценарий:

USER ACTION
→ MENU
→ ROUTER
→ MODULE
→ RESPONSE

Для stateful-модуля дополнительно:

ENTER MODULE
→ MESSAGE
→ MODULE RESPONSE
→ EXIT MODULE
→ MESSAGE
→ MODULE MUST NOT RECEIVE MESSAGE

## 8. Production verification

После deploy необходимо проверить реальное поведение приложения.

Успешный deploy сам по себе не считается успешным тестом.

## 9. Definition of verified

Изменение считается проверенным только если:

- модуль работает;
- Router работает;
- пользовательская точка входа работает;
- другие модули не перехватывают событие;
- старая реализация не активна;
- полный пользовательский сценарий работает.
