# SecretTalk — Architecture Preflight

## 1. Назначение

Этот документ определяет обязательную проверку перед началом любого архитектурного изменения.

Preflight выполняется до создания, изменения, перемещения или удаления кода.

## 2. Проверка функции

Определить:

- что именно создаётся или изменяется;
- какую функцию выполняет изменение;
- существует ли такая функция уже;
- какой модуль сейчас является её владельцем.

## 3. Проверка существующей реализации

Найти:

- текущий модуль;
- текущий обработчик;
- текущий Router route;
- текущую кнопку или команду;
- старые сервисы;
- старые зависимости;
- возможные дубли.

Нельзя создавать новую реализацию, пока не понятно, что происходит со старой.

## 4. Определение точки входа

До реализации определить:

`USER ACTION → ROUTER → MODULE`

Если пользовательской точки входа нет, определить другой предусмотренный архитектурой способ запуска.

## 5. Проверка Index

Определить, требуется ли изменение `index.js`.

По умолчанию:

`INDEX = NO`

Изменение `index.js` разрешается только для root-level lifecycle integration.

## 6. Проверка Menu

Определить, требуется ли:

- кнопка;
- команда;
- callback;
- keyboard;
- другой пользовательский entrypoint.

Если требуется, заранее определить его владельца и маршрут.

## 7. Проверка старого кода

Определить:

- что будет заменено;
- какие старые файлы станут неактивными;
- какие старые импорты нужно удалить;
- какие старые маршруты нужно удалить.

## 8. План

До начала реализации должен существовать следующий план:

CREATE
→ VERIFY
→ REGISTER
→ INTEGRATE
→ REMOVE OLD
→ VERIFY
→ COMMIT
→ DEPLOY
→ TEST

## 9. Запрет начала работы

Если хотя бы один из следующих пунктов неизвестен:

- владелец функции;
- точка входа;
- Router route;
- необходимость Menu;
- необходимость Index;
- старая реализация;

реализация не начинается.

Сначала определяется архитектура.

## 10. Завершение Preflight

Preflight считается завершённым только после того, как определены:

- модуль;
- файлы;
- публичный интерфейс;
- Router integration;
- UI integration;
- Index integration при необходимости;
- старая реализация;
- способ удаления старой реализации;
- способ проверки.

После этого начинается CREATE.
